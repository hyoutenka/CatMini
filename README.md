# 프로젝트 F: 미니게임 규칙 코드

Unity 프로젝트에서 분리한 C# 규칙 코드다. 장난감 입력과 점수 판정 중 Unity에 의존하지 않는 부분만 담았다. 본게임의 씬, UI, 고양이 데이터, 이미지, 음원은 포함하지 않았다.

## 미니게임 안내

본게임에서는 경계형 고양이에게 맞는 장난감을 사용해 미니게임을 시작한다. 낚싯대, 레이저 포인터, 호루라기 세 종류가 있다. 성공하면 고양이의 경계가 풀리고 사진 촬영은 별도로 진행된다. 실제 플레이에서 실패하면 고양이가 도주하지만, 데이터나 화면 문제로 시작하지 못한 경우에는 도주하지 않는다. 이러한 진입과 결과 처리는 이 저장소에 포함되지 않는다.

공통 흥미도는 30에서 시작해 0~100 범위에서 움직인다. 100이면 성공, 0이면 실패다. 낚싯대와 레이저 포인터는 흥미 상태를 유지하는 동안 초당 18점이 오르고, 경계 상태에서는 초당 10.5점이 내려간다. 호루라기는 입력마다 점수를 바꾸지 않고 라운드가 끝날 때만 반영한다.

| 장난감 | 본게임 조작과 판정 | 이 저장소의 코드 |
| --- | --- | --- |
| 낚싯대 | 마우스로 미끼를 움직이고 버튼을 놓을 때 한 번 판정한다. 가까운 지점을 연속해서 놓으면 감점된다. | 확정 지점의 거리와 관심 축적 규칙 |
| 레이저 포인터 | 방향키 또는 WASD로 안전한 영역 안에서 레이저를 좌우로 흔든다. 몸통이나 바닥 경계에 닿으면 경계 상태가 된다. | 포함하지 않음 |
| 호루라기 | Space로 라운드를 시작하고 Q/W/E를 타이밍에 맞춰 누른다. | 라운드 점수와 콜드게임 판정 규칙 |

낚싯대는 처음 놓은 지점을 기준점으로 삼는다. 확정 지점 사이 거리가 20 미만인 이동이 연속되면 두 번째부터 매번 6점이 깎인다. 관심을 만들려면 안전한 영역에서 앞선 유효 지점과 80 이상 떨어진 곳으로 0.2~1.2초 간격으로 이동해야 한다. 유효 이동 세 번부터 흥미 상태가 유지된다. 공개 코드는 거리와 간격을 판정하며, 감점 적용과 화면 표시는 본게임에서 처리한다.

호루라기는 라운드마다 다섯 번의 입력을 판정하고 최대 다섯 라운드를 진행한다. 맞는 키를 각 시도 진행률의 42~58% 구간에 누르면 성공이다. 라운드에서 다섯 번 모두 성공하면 27.5점, 2~4번 성공하면 17.5점, 0~1번 성공하면 10점이 깎인다. 남은 라운드에서 모두 최고 점수를 받아도 흥미도 100에 도달할 수 없으면 콜드게임으로 종료한다. 공개 코드는 점수와 콜드게임을 계산하며, QTE 입력과 소리, 화면은 포함하지 않는다.

## 포함된 파일

| 파일 | 현재 게임에서의 역할 |
| --- | --- |
| `src/WhistleRoundRules.cs` | 호루라기 5회 입력 라운드의 점수와 남은 라운드로 목표 달성이 가능한지 계산한다. |
| `src/FishingRodMovementTracker.cs` | 낚싯대 클릭과 드래그 확정 지점의 거리, 연속된 짧은 이동을 판정한다. |
| `src/FishingRodAttentionTracker.cs` | 낚싯대의 입력 거리와 간격을 세어 관심 상태를 만든다. |

세 파일은 일반 C# 프로젝트에 복사하거나 Unity 프로젝트의 스크립트로 가져올 수 있다. 방향키로 조작하는 현재 레이저 포인터 게임과 미니게임 화면은 이 패키지만으로 실행되지 않는다. `WhistleRoundRules.Score()`는 성공 횟수 0~5만 받으며, 범위를 벗어나면 `ArgumentOutOfRangeException`을 던진다.

낚싯대 좌표는 동일한 좌표계로 입력한다. 본게임에서는 UI 로컬 좌표를 사용한다. `FishingRodMovementTracker`는 입력 시작에 `Begin(x, y)`, 놓을 때 `Complete(x, y)`를 호출해 한 번 판정한다. `FishingRodAttentionTracker`는 경과 시간을 초 단위로 `Tick(dt)`에 전달하고, 확정 지점을 `RegisterPoint(x, y)`에 전달한다. `WhistleRoundRules.CanReachTarget()`에는 본게임에서 현재 흥미도 0~100, 완료한 라운드 수 0~5, 목표 100을 전달한다.

## 실행 및 검증

.NET 10 SDK를 설치한 뒤 이 폴더에서 다음 명령을 실행한다.

```sh
dotnet run --project tests/WhistleRoundRules/WhistleRoundRules.Tests.csproj
dotnet run --project tests/FishingRodMovementTracker/FishingRodMovementTracker.Tests.csproj
```

두 테스트는 `dotnet test`가 아닌 콘솔 검증 프로그램이며 별도 NuGet 패키지 없이 실행된다. 호루라기의 점수와 콜드게임, 확정 지점 거리, 클릭과 드래그의 일치, 입력 간격 경계와 프레임 분할에 따른 관심 판정을 확인한다.

호루라기 점수 변화는 다음 예제로 확인할 수 있다.

```sh
dotnet run --project examples/ScoreExplorer/ScoreExplorer.csproj -- 2 5 0 3
```

인수 하나가 한 라운드의 성공 횟수(0~5)다. 예제는 실제 코드의 라운드 점수, 0~100 제한, 조기 실패 조건을 적용한다. QTE 키 입력의 타이밍, 소리, 화면은 재현하지 않는다.

## 포크 후 확장

- 호루라기의 성공 구간과 점수를 설정값으로 분리할 수 있다.
- 낚싯대 입력 판정과 화면 입력 연결을 분리해 다른 조작으로 확장할 수 있다.
- 새 입력 순서에 대한 테스트를 추가할 수 있다.
- 플레이 가능한 Unity 데모를 만들려면 씬, 입력 연결, 화면, 공개 가능한 샘플 아트가 별도로 필요하다.

규칙을 바꾸면 달라진 동작을 기록하고 두 테스트를 다시 실행한다. 이 폴더의 내용만 저장소 루트로 사용한다. 본게임의 `Assets`, `Resources`, `Marketing`, 빌드 폴더는 포함하지 않는다.
